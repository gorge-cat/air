## 1. 这个程序到底在干什么

### 1.1 生活类比

想象你有一个 10 米×10 米×10 米的大房间（比普通客厅大一些，像个小仓库）。夏天室外 35°C，屋里也被晒到 35°C。现在你装了一台 1.5 匹空调在房间正中央的天花板附近，想把它降到 25°C。

**程序做的事就是"用电脑模拟这个过程"**：

1. **把房间切成小盒子**：把 10m 长切成 20 段，每段 0.5m。于是整个房间变成 20×20×20 = **8000 个 0.5m 的小立方体盒子**，每个盒子记一个温度值。

2. **每 0.2 秒重新算一次**：算这 0.2 秒里——
   - 谁在给每个小盒子加热（太阳、外墙、人、电脑、灯）
   - 空调给某些小盒子送了多少冷气
   - 冷气怎么顺着气流流向下一个盒子（对流）
   - 相邻盒子的温度怎么互相渗透（扩散）
   - 热气往上飘、冷气往下沉时怎么自动搅匀（浮力搅拌）

3. **重复 6 小时**（共 108000 步），每隔 30 秒记一次"快照"。

4. **对比 6 种用法**，看哪种最省电、最快降温、温度最均匀。

### 1.2 为什么叫 "turb"（turbulent 湍流）

因为程序用了一个简化的"湍流扩散"模型——空调吹出的射流（jet）附近空气搅动剧烈（扩散系数大），远离射流的角落空气几乎不动（扩散系数小）。这不是真正的流体力学方程（NS 方程），而是**工程化的简化模型**，跑得快但能看出趋势。

### 3.1 制冷与送风

| 参数 | 数值 | 大白话含义 | 代码行 |

> **COP 是什么？** Coefficient of Performance（性能系数）。COP=3.2 意思是：消耗 1W 电，能搬运 3.2W 的热量。COP 越高越省电。变频空调在低负载时 COP 会更高（能省电），这个参数就是模拟这个特性。

| 参数 | 数值 | 含义 | 代码行 |

| `fan_power_nominal` | 80 W | 风机额定功率（满风量时） | :50 |
| `fan_ratio_min` | 0.35 | 风机最低转速比例 35%（变频机最低风量） | :51 |
| `compressor_ratio_min` | 0.20 | 压缩机最低运行比例 20%（低于此就停机） | :52 |

### 3.3 控制器参数（仅变频机用）

| 参数 | 数值 | 含义 | 代码行 |
|------|------|------|--------|
| `controller_Kp` | 0.08 | 比例系数 P：温度每偏离目标 1K，制冷比例调整 8% | :53 |
| `controller_Ki` | 4.0e-5 | 积分系数 I：累积误差的修正力度（很小，慢慢调） | :54 |
| `controller_integral_band` | 2.5 K | 积分起作用区间：误差 ≤2.5K 才积分，否则怕超调 | :55 |

> **定频 vs 变频（核心区别）**：
> - **定频 (AlwaysOn)**：压缩机永远 100% 输出，达到目标温度后只能"停机-重启"循环，温度波动大、费电。
> - **变频 (Inverter)**：压缩机能在 20%~100% 之间无级调节，温度稳、省电、舒适。代码里 `inverter=true/false` 控制（:106）。

## 4. 六种对比方案

代码位置：`room_ac_turb.m:99-106`

```
方案编号  方向角  方向dir  变频?   名称                    生活场景对应
  ①      +30°    +1       否     Up + AlwaysOn          上吹+定频（老式柜机）
  ②      +30°    +1       是     Up + Inverter          上吹+变频（常见家用壁挂/柜机）
  ③       0°      0       否     Horizontal + AlwaysOn  平吹+定频
  ④       0°      0       是     Horizontal + Inverter  平吹+变频（中央空调侧送）
  ⑤      -30°    -1       否     Down + AlwaysOn        下吹+定频
  ⑥      -30°    -1       是     Down + Inverter        下吹+变频（顶送下回办公空调）
```

### 三种送风方向解释

- **上吹 +30°**：空调出风口朝**斜上方**吹。冷气先冲向天花板，然后沿天花板铺开再下沉。常见于壁挂机装得低、导风板朝上的场景。
- **平吹 0°**：空调出风口**水平**吹。冷气直射房间另一端，射程最远。常见于中央空调侧送风。
- **下吹 -30°**：空调出风口朝**斜下方**吹。冷气直接砸向地面，地面先凉。常见于顶送风办公空调。

> **为什么对比这些？** 因为不同送风方向会导致完全不同的温度分布——上吹可能"头热脚凉"，下吹可能"头凉脚热"，平吹可能"远处冷近处热"。这个程序就是要量化这些差异。

稳态下大概：

- 设备+照明：600 W
- 太阳：~425 W（平均值）

## 6. 程序怎么"算"的——核心 4 步循环

代码位置：主循环 `room_ac_turb.m:188-243`

每 0.2 秒做一次下面 4 步：

### 6.1 第一步：算热负荷（谁在给每个格子加热）

函数：`heatLoadRate`（`:376-388`）

```
对每个小格子 i：
  热量[i] = 围护传热[i] + 人员设备照明[i] + 太阳[i]
```

- 围护传热 = `conductance[i] × (T_outdoor - T[i])`，格子越靠外墙传热越多
- 人员/设备/照明 = 总内部热 × 空间权重（只加在活动区）
- 太阳 = 太阳功率 × 空间权重（只加在东墙+顶棚）

**输出**：`heatRateField`（每个格子的加热功率 W）、`totalHeatLoad`（全屋总热负荷 W）、`outdoorTemperature`（当前室外温度 K）。

### 6.2 第二步：算空调制冷（冷气怎么铺开）

这部分分两小步：先算空调出力，再把冷量分配到各个格子。

#### 6.2.1 空调出力（`airConditionerPerformance`，`:422-443`）

输入：压缩机比例 `compressorRatio`（0~1）、回风温度 `returnTemperature`。

```
fanRatio = 0.35 + 0.65×√(compressorRatio)     # 风机转速
massFlow = 0.2 × fanRatio                       # 风量(kg/s)
fanPower = 15 + 65×fanRatio³                    # 风机耗电(W)

if 压缩机停了:
    制冷=0, 耗电=风机功率
else:
    请求制冷 = compressorRatio × 3500
    风侧极限 = massFlow × 1005 × (回风温度 - 14°C)   # 风量×比热×最大温差
    实际制冷 = min(请求制冷, 风侧极限)              # 取较小值
    送风温度 = 回风温度 - 实际制冷/(massFlow×1005)
    COP = 3.2 + 0.5×(1-compressorRatio)            # 低负载COP更高
    耗电 = 制冷/COP + 风机功率
```

> **关键点**：制冷量受两个限制——①压缩机能力（比例×3500），②风侧能力（风量×温差）。即使压缩机满载，如果风量太小或温差太大，实际制冷也上不去。

#### 6.2.2 冷量空间分配（`buildJetFields`，`:343-374`）

空调冷气不是均匀洒向全屋，而是沿**射流路径**集中分布。

**射流形状建模**（这是本程序最精巧的部分）：

1. **射流中心线**（`:350-353`）：
   ```
   中心高度 = 5m + x × tan(角度)
   # 上吹30°：每前进1米升高0.577米
   # 平吹0°：高度始终5米
   # 下吹-30°：每前进1米下降0.577米
   # 撞到顶/底后转为水平贴壁（:351-352）
   ```

2. **射流横截面**（高斯分布，`:357-358`）：
   ```
   距中心线的径向距离² = (y-5)² + (z-中心高度)²
   jetCore = exp(-径向距离² / (2×半宽²))
   # 中心最强=1，往外指数衰减
   # 半宽随x增大：0.35 + 0.10×x（越远越散，:354）
   ```

3. **轴向衰减**（`:359`）：
   ```
   axialDecay = exp(-x / (10×0.8)) = exp(-x/8)
   # 吹出8米后强度剩37%，吹出16米剩13%
   ```

4. **最终冷量权重**（`:364-365`）：
   ```
   rawWeight = 0.002 + jetCore × axialDecay
   coolingWeight = rawWeight / sum(rawWeight)   # 归一化，总和=1
   # 0.002是给远离射流的角落留一点点背景冷量
   ```

**冷量分配公式**（`:203`）：
```
每个格子降温 = (dt / cellCapacity) × (热量[i] - 制冷功率 × coolingWeight[i])
# cellCapacity = 1.2×1005×0.5³ = 150.75 J/K
# 一个格子升温1K需要150.75焦耳
```

#### 6.2.3 速度场（射流怎么推空气，`:367-373`）

```
uJet = 1.2 × jetWeight          # x方向速度（射流前进）
uFull = uJet - mean(uJet)       # 减去均值，保证总体积守恒
wJet = uJet × tan(角度)         # z方向速度（上吹则向上）
wFull = wJet - mean(wJet)       # 同样减均值
# 撞墙后verticalSlope=0，转为水平贴壁（:371）
```

> **为什么减均值？**（`:459`）房间是封闭的，空气不能凭空产生或消失。射流核心向前推，必然有等量空气向后回流（就像地铁进站时车头推空气、车尾吸空气）。减去全域均值就是模拟这个"净流量为零"的约束。

### 6.3 第三步：对流 + 扩散（冷气怎么流、怎么混）

#### 6.3.1 对流项（`advectionIncrement`，`:445-460`）

用**一阶迎风格式**离散：温度被气流"搬运"到下游。

```
对流增量 = -u×(dT/dx) - w×(dT/dz)
# 用"上游"格子的温度来算下游的变化（迎风）
# u>0 用左边格子，u<0 用右边格子
```

代码里把速度拆成正负两部分（`:136-139`）分别处理：
```
uPositive = max(u, 0)   # 向右流的部分
uNegative = min(u, 0)   # 向左流的部分
```

**最后减去全域均值**（`:459`）：因为简化速度场不是逐格严格无散度，封闭房间对流只能"搬运"不能"创造"温度，所以投影掉净增量防止对流变成虚假热源。

#### 6.3.2 扩散项（`diffusionIncrement`，`:462-477`）

模拟相邻格子温度互相渗透（热传导+湍流混合）。

```
通量 = (背景扩散 + 风机比例×射流扩散) × (T邻 - T本)
# 背景扩散 alpha_bg=0.003 全屋都有
# 射流扩散 alpha_jet×jetWeight 只在射流区，且随风机转速缩放
# 无通量边界（外墙不漏热给外界，热负荷另算）
```

**守恒离散**：每个面的通量从一边加、另一边减，总能量严格守恒（`:466-476`）。

### 6.4 第四步：浮力搅拌（`applyBuoyancyMixing`，`:479-497`）

每 1 秒做一次（`:84` `mixEvery`）。模拟热空气上浮、冷空气下沉的自然对流。

```
对每对相邻高度层(z, z+1)：
  垂直温差 = T[z+1] - T[z]   # 上层减下层

  if 温差 < -0.3K:    # 上层比下层冷（不稳定，要翻腾）
      Ri = |温差|/2
      混合系数 = min(0.15, 0.05×(1+Ri))   # 越不稳混合越强，上限0.15
  elif 温差 > 0.3K:   # 上层比下层热（稳定分层，但仍微弱混合）
      Ri = 温差/2
      混合系数 = max(0.005, 0.03/(1+Ri))  # 越稳混合越弱，下限0.005
  else:               # |温差|≤0.3K，几乎不处理

  交换量 = 0.5 × 混合系数 × 温差
  T[z]   += 交换量
  T[z+1] -= 交换量    # 守恒：上下层一加一减
```

> **Richardson 数**是真实流体力学里判断分层稳定性的指标。这里用简化版：温差越大、且是"上冷下热"就越不稳定（强混合）；"上热下冷"就越稳定（弱混合）。

### 6.5 主循环时间轴

```
每 0.2 秒：       热负荷 → 空调出力 → 对流 → 扩散 → 温度更新
每 1 秒（5步）：   浮力搅拌一次
每 30 秒：        记录一次快照（温度场+各项指标）
每 ~36分钟：      打印进度
满 6 小时：       结束，绘图保存
```

## 7. 变频控制器——空调的"大脑"

代码位置：`compressorController`，`:390-420`

### 7.1 定频机（简单粗暴）

```matlab
if ~useInverter
    ratio = 1;    % 永远100%输出
    return;
end
```
（`:392-395`）压缩机要么满载要么停机，没有中间状态。

### 7.2 变频机（前馈 + PI 反馈 + 抗饱和）

#### 7.2.1 前馈（预判，`:397`）
```
feedForward = min(1, max(0, 热负荷/3500))
# 直接按热负荷比例给初值：热负荷2000W→前馈0.57
```
好处：温度还没变化就先调好出力，反应快。

#### 7.2.2 积分项（消除稳态误差，`:398-403`）
```
if |误差| ≤ 2.5K:    # 只在接近目标时才积分，防止远处累积过大
    积分 += 4e-5 × 误差 × dt
    积分 = clip(积分, -0.5, +0.5)   # 限幅
else:
    积分保持不变     # 远离目标时冻结
```
好处：消除"差一点点永远到不了目标"的稳态误差。

#### 7.2.3 比例项（`:404`）
```
比例 = 0.08 × 误差
# 误差+1K（偏热1度）→ 比例项+0.08，出力增加8%
```

#### 7.2.4 条件积分抗饱和（`:407-410`）
```
if 已经饱和(>1)且误差继续推向饱和方向(>0):
    暂停积分   # 别再往饱和方向积了
elif 已经饱和(<0)且误差继续推向饱和方向(<0):
    暂停积分
else:
    接受积分更新
```
好处：防止积分器在饱和时疯狂累积，解除饱和后严重超调。

#### 7.2.5 最终输出（`:411`）
```
ratio = clip(0, 1, 前馈 + 比例 + 积分)
```

#### 7.2.6 最小运行比例保护（`:413-419`）
```
if 0 < ratio < 0.20:    # 低于最小运行比例
    if 误差 > -0.25K 或 前馈 > 0.10:
        ratio = 0.20     # 强制拉到最小运行（避免频繁启停）
    else:
        ratio = 0        # 否则直接停机
```
好处：变频机不会在 5% 这种低效区间憋着烧电，要么至少 20% 运行，要么停。

### 7.3 用开车类比理解 PI 控制

- **前馈** = 看到前方上坡，提前踩油门（不等速度掉下来就加力）
- **比例 P** = 速度低于目标越多，踩油门越深（当前误差立即反应）
- **积分 I** = 速度一直差一点点，慢慢把油门加到刚好（消除长期偏差）
- **抗饱和** = 油门已经踩到底了就别再踩了（防止解除后猛冲）

## 8. 稳定性检查——为什么时间步必须 0.2 秒

代码位置：`:72-77`、`:124-135`

### 8.1 扩散稳定性限制（`:72-77`）

显式离散扩散方程要求：
```
dt ≤ dx² / (6 × alpha_max)
   = 0.5² / (6 × (0.003 + 0.04))
   = 0.25 / 0.258
   = 0.969 秒
```
程序里如果 `dt > 0.969` 会直接报错（`:74-77`）。0.2 秒远小于此限制，安全。

### 8.2 对流+扩散组合稳定性（`:124-135`）

```
CFL数 = dt/dx × max(|u|+|w|)
扩散数 = 6 × alpha_max × dt / dx²
组合数 = CFL + 扩散数
要求：组合数 ≤ 0.95
```

如果超 0.95 程序会报错并建议最大允许 dt（`:130-134`）。0.2 秒下这两个数都很小，组合稳定。

> **为什么要检查？** 显式格式（每步用当前状态直接算下一步）有稳定性限制：步长太大，数值会震荡发散，算出几千度的荒谬结果。CFL 数本质是"一个时间步内信息传播不能超过一个网格"。

### 8.3 程序里的"防爆炸"检查

`:214-217`：每步检查温度是否变成 NaN/Inf，如果是就立刻报错并报告时间点。这是数值发散的最后一道防线。

| 方案 | 预期降温速度 | 原因 |

- **定频**：达温后只能停机→温度回升→重启→过冷，**波动 ±1~2K**

## 附录 B：常见疑问

**Q1：为什么房间是 10m×10m×10m？这么大的房间用 1.5 匹够吗？**
A：这是个偏大的空间（1000m³），1.5 匹（3500W）其实偏小。程序目的是对比送风方式和控制策略，不是设计实际工程。实际 1000m³ 空间至少要 5 匹以上。

**Q2：为什么网格只切 20×20×20？切细点不更准吗？**
A：切细点更准但更慢。20³=8000 格，每步要算 8000 个格子的对流扩散，6 小时×5 步/秒=108000 步，总共约 8.6 亿次格子更新。切 40³ 就要 8 倍时间。这是精度和速度的权衡。

**Q3：射流模型是真的 CFD 吗？**
A：不是。这是**工程简化模型**——用高斯分布+轴向衰减近似射流形状，用增强扩散系数近似湍流混合。真正的 CFD 要解 Navier-Stokes 方程（如 OpenFOAM/Fluent），计算量大 100 倍以上。本程序牺牲精度换速度，适合做趋势对比。

**Q4：定频机为什么不模拟启停循环？**
A：代码里定频机 `ratio=1` 永远满载（`:393-394`），没有"达温停机"逻辑。这是简化——真实定频机达温后会停启循环。如果要模拟，需要在控制器里加温度滞后回差（比如低于 24°C 停、高于 26°C 启）。

**Q5：浮力搅拌为什么每 1 秒做一次而不是每步？**
A：浮力效应相对慢，每步做没必要且增加计算量。每 5 步（1 秒）做一次是合理折衷（`:84` `mixEvery`）。

**Q6：为什么冷量权重要加 0.002 的背景值？（`:364`）**
A：保证远离射流的角落也能分到一点点冷量。如果不加，角落格子 coolingWeight=0，只能靠扩散慢慢降温，可能永远降不下来。0.002 是个小值，不影响射流区主导，但给角落留了"呼吸口"。
